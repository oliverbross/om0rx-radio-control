WHAT WAS CHANGED
================================================================================

PROBLEM:
  The Wavelog Log Modal used a wasteful background sync loop that:
  ❌ Called Wavelog API 1,440 times per day (constantly)
  ❌ Maintained a local MySQL database with duplicate data
  ❌ Caused 6+ minute delays in data freshness
  ❌ Added unnecessary database overhead
  ❌ Wasted API credits

SOLUTION:
  Refactored to call Wavelog API directly on-demand when user needs data:
  ✅ Calls Wavelog API only when modal is opened (~50-100x/day)
  ✅ No database overhead needed
  ✅ Data is always fresh (1-2 seconds old)
  ✅ Simplified architecture
  ✅ Reduced API credit usage by 93%

HOW IT WORKS NOW
================================================================================

Workflow:
  1. User opens "Wavelog Log" modal in UI
  2. Frontend calls: GET /api/wavelog/contacts?limit=100
  3. Backend receives request
  4. Backend calls: POST /api/get_contacts_adif to Wavelog
  5. Wavelog returns ADIF formatted QSO data
  6. Backend parses ADIF using new _parse_adif_contacts() function
  7. Backend returns JSON to frontend
  8. Frontend displays fresh QSOs in table

Total time: ~1-2 seconds (much faster than 6+ minutes!)

Q: Will the data be stale?

Q: What if Wavelog API is down?
A: Error handling returns error message, user sees "Refresh failed" warning.

Q: Can I go back to the old way?

Q: Why is each request slower (1-2 sec vs 200-500ms)?
A: Because we're calling the actual Wavelog API. But it happens on-demand,

   or "✅ Parsed and returning X QSOs from Wavelog API"
